# HashDict —— 基于哈希表的命令行英语词典

一个用 **纯 C** 写的命令行英语词典引擎。把约 2 万个词条从文本文件加载进
**自实现的哈希表**（链地址法 + 动态扩容），实现 O(1) 期望时间查词，并附带
前缀补全、拼写纠错、生词本、查询历史、性能基准等功能。

整个项目不依赖任何第三方库，只用 C 标准库和少量 POSIX 接口，`make` 一键编译。

## 为什么写它

课程作业里的查词程序，典型写法是**每查一个词就把整个词典文件从头扫一遍**
（`fgets` + `strcmp` 循环），单次查询 O(n)；或者引入 SQLite 把查询交给数据库。

本项目换一个思路：**程序启动时把整本词典一次读进内存里的哈希表**，
之后每次查询都是 O(1) 期望时间。数据来源仍是纯文本 `dict.txt`，
但查询性能有数量级的提升，同时也把「哈希表 + 链表 + 顺序表 + 文件 IO」
这几块数据结构与系统编程的基础落到一个能跑、能讲、能量化的完整项目里。

## 功能特性

| 功能 | 说明 |
|------|------|
| 精确查询 | 大小写不敏感，`Apple` 和 `apple` 都能查到 |
| 前缀补全 | `:prefix aband` 列出所有以该前缀开头的单词 |
| 拼写纠错 | 查不到时用**编辑距离**给出「你是不是想查」，如 `abandom → abandon` |
| 生词本 | `:add` / `:del` 增删，持久化到 `~/.hashdict/favorites.txt` |
| 查询历史 | 自动记录查过的词，持久化到 `~/.hashdict/history.txt` |
| 随机单词 | `:random`，用蓄水池抽样保证每个词等概率 |
| 词频分布 | `:dist` 打印首字母分布柱状图 |
| 运行统计 | `:stats` 显示装载因子、最长冲突链、非空桶比例等 |
| 性能基准 | `:bench <词>` 实测量化「哈希查询 vs 线性扫描」的加速比 |
| 热加载词典 | `:load <文件>` 运行时换词典，走完整的内存释放与重建 |
| 命令行模式 | 支持 `./hashdict <词>` 单次查询、`-p` 前缀、`-b` 基准 |
| 彩色输出 | 终端下自动着色，重定向到文件时自动去掉转义码 |

## 编译与运行

需要 `gcc` 和 `make`（Linux / WSL / macOS 均可，Windows 下 MinGW 也能编译）。

```bash
make            # 编译，生成可执行文件 hashdict
make run        # 编译并直接进入交互模式
make debug      # 带 AddressSanitizer/UBSan 的调试版（抓内存问题）
make memcheck   # 用 valgrind 做内存检查
make clean      # 清理
```

## 设计说明

数据流：

```
                加载阶段（一次）
  dict.txt ──fgets──> 逐行解析 ──ht_insert──> 哈希表(常驻内存)
                                                 │
                查询阶段（每次 O(1)）              │
  用户输入 ──归一化──> ht_find ──────────────────┘
                         │
                         └─> 命中：打印释义 / 未命中：编辑距离纠错
```

哈希表结构（链地址法）：

```
 buckets[]      entry          entry
 ┌───────┐
 │   ●───┼──> [word|meaning] ─> [word|meaning] ─> NULL   ← 冲突链
 ├───────┤
 │ NULL  │
 ├───────┤
 │   ●───┼──> [word|meaning] ─> NULL
 └───────┘
   16384 个桶，装载因子 > 0.75 时翻倍并 rehash
```

模块划分（每个模块职责单一，头文件即接口）：

- `util`：时钟、字符串、跨平台目录/终端判断
- `hash`：哈希表本身（增删查、扩容、统计），**不关心「词典」这个概念**
- `store`：顺序表 `strlist`，以及生词本/历史的持久化
- `fuzzy`：编辑距离
- `dict`：词典业务层，把文件读进哈希表并提供各种查询
- `cli`：命令行交互层
- `main`：参数解析与流程编排

## 关键实现点

**1. 哈希函数：BKDR Hash（种子 131）**
逐字符 `h = h * 131 + c`，分布均匀且实现极简。先统一转小写再计算，
使大小写不同的写法落在同一个桶，配合大小写不敏感的比较实现「输入不挑大小写」。

**2. 动态扩容（rehash）**
装载因子 `count / nbuckets` 超过 0.75 就把桶数翻倍，把旧表所有结点重新挂到
新桶上。扩容只搬指针、不复制字符串，很快。这保证了链表不会退化，
查询始终维持在 O(1) 期望。

**3. 处理真实数据的两个坑**
- **CRLF 行尾**：词典是 Windows 行尾（`\r\n`），若不剥掉 `\r`，每个单词尾部都会
  多一个不可见字符，导致永远查不到。加载时用 `util_trim` 一并去掉。
- **折行释义**：极少数释义会折到下一行（以空白开头）。加载器检测到这种续行时，
  把内容合并回上一个单词，保证释义完整。

**4. 编辑距离剪枝**
朴素 Levenshtein 是 O(m×n)。这里做了三重剪枝：长度差超限直接放弃、
两行滚动数组省内存、某一行最小值已超上限就提前退出。这样才能在
2 万个词里做实时模糊匹配而不卡顿。

**5. 不用 `gets`**
原版常用 `gets`，它无法限制长度、已从 C11 标准中移除。本项目统一用
`fgets` + `util_trim`，从根本上避免缓冲区溢出。

## 性能数据

词典规模 **19626** 词条，最终稳定在 **32768** 个桶：

| 指标 | 数值 |
|------|------|
| 装载因子 | 0.599（上限 0.75） |
| 非空桶数 | 14805（45.2%） |
| 最长冲突链 | 6 |
| 非空桶平均链长 | 1.33 |

查询性能（`./hashdict -b abandon`，开发机实测）：

| 方式 | 单次平均耗时 |
|------|-------------|
| 哈希查询 | 约 125 ns |
| 线性扫描 | 约 410 μs |
| **加速比** | **约 3280 倍** |

> 注：具体数字随机器变化，用 `:bench` 可在自己的机器上复现。哈希查询的
> 耗时几乎与词典规模无关，而线性扫描会随词条数线性增长——这正是哈希表的价值。

## 可扩展方向

- **客户端 / 服务端**：词典只加载一次常驻内存，服务端监听 Unix domain socket，
  `fork` 出子进程处理并发查询，客户端连接后查询。这样可以避免每个终端
  重复加载 2 万词（当前每次启动约 200 ms），是进程编程 + IPC 的天然练习。
- **多线程加载**：把文件分块并行解析，进一步压缩启动时间。
- **词典文件格式**：支持 JSON/CSV，或中英双向词典。
- **单元测试**：把 `tests/run_tests.sh` 扩展为更系统的断言集合。
